1. Configuración de VirtualBox e instalación de Ubuntu

Creación de la máquina virtual

En VirtualBox se creó una máquina nueva y se seleccionó la ISO de Ubuntu 26.04.1. Se activó «Omitir instalación desatendida» para completar manualmente el asistente y el particionado. La configuración inicial fue de 6144 MB de RAM, dos procesadores y un disco virtual de 50 GB.

Se mantuvo desactivada la opción EFI. Por ello Ubuntu se instaló inicialmente en modo BIOS, aunque el disco ya utilizaba una tabla de particiones GPT.

Instalación y particionado de Ubuntu

Desde el instalador se configuraron el idioma y el teclado en español, la zona horaria y la cuenta de usuario. Se eligió el particionado manual para determinar los puntos de montaje y los tamaños de cada partición.

3. Gestión de paquetes con APT, Aptitude y dpkg

APT: instalación y eliminación de VLC

Se consultó primero si VLC estaba disponible, se actualizó el índice de los repositorios y se instaló el reproductor. Después se abrió para comprobar su funcionamiento. Finalmente, se desinstaló y se eliminaron las dependencias innecesarias.

apt-cache policy vlc
sudo apt update
sudo apt install vlc
vlc
sudo apt remove vlc
sudo apt autoremove
apt-cache policy vlc

Aptitude: gestión de SMPlayer

Se utilizó aptitude show para consultar los detalles del paquete, aptitude update para actualizar la información de los repositorios y aptitude install para instalar SMPlayer resolviendo sus dependencias. Tras ejecutarlo, se eliminó con purge, que también retira sus archivos de configuración administrados por el paquete.

aptitude show smplayer
sudo aptitude update
sudo aptitude install smplayer
smplayer
sudo aptitude purge smplayer
aptitude show smplayer

dpkg: instalación local de Pacman

Desde Descargas se consultó el estado del paquete y se revisó la información del archivo .deb. Con dpkg -i se instaló el juego, se comprobó que podía ejecutarse y se eliminó con dpkg -r.

cd ~/Descargas
dpkg -l pacman
dpkg -I pacman*.deb
sudo dpkg -i pacman*.deb
pacman
sudo dpkg -r pacman
dpkg -l pacman

4. Eliminación de /boot y recuperación del arranque

Eliminación de /boot y aparición de GRUB Rescue

Como ejercicio de recuperación, se desmontó /boot y se eliminó la ruta indicada. Tras el reinicio, el gestor de arranque no encontró el módulo /grub/i386-pc/normal.mod y apareció la consola grub rescue>.

sudo umount /boot
sudo rm -rf /boot

Atención: estos comandos se muestran como parte del ejercicio realizado en una máquina virtual; no deben ejecutarse en un sistema que se quiera conservar operativo.

Primer intento: Super Grub2 Disk

Se conectó la ISO de Super Grub2 Disk desde Configuración → Almacenamiento y se inició la máquina desde la unidad óptica. Se utilizaron las opciones de búsqueda automática, pero no se logró arrancar el Ubuntu instalado.

Segundo intento: Boot-Repair

Se sustituyó la ISO anterior por Boot-Repair-Disk y se inició la reparación automática. La herramienta mostró el mensaje linux-generic purge cancelled y el intento no finalizó correctamente.

Tercer intento: recuperación con la ISO de Ubuntu

Se inició la ISO de Ubuntu en modo «Probar Ubuntu». Desde esa sesión temporal se montaron las particiones del sistema dañado para repararlo sin reinstalar Ubuntu.

sudo mount /dev/sda4 /mnt
sudo mkdir -p /mnt/boot
sudo mount /dev/sda2 /mnt/boot
sudo mount /dev/sda5 /mnt/tmp

Luego se montaron los directorios necesarios para acceder a los dispositivos y procesos del sistema y se utilizó chroot para ejecutar los comandos dentro de la instalación averiada.

for i in /dev /dev/pts /proc /sys /run; do
  sudo mount --bind "$i" "/mnt$i"
done
sudo chroot /mnt /bin/bash

Reinstalación del kernel y de GRUB para BIOS

Dentro de chroot se identificó el kernel instalado y se reinstaló. Esta operación regeneró los archivos vmlinuz e initrd. Después se reinstaló GRUB en el disco y se actualizó su menú; al comprobar el contenido de /boot se observaron de nuevo los archivos de arranque.

dpkg -l | grep linux-image
apt update
apt install --reinstall linux-image-7.0.0-34-generic
grub-install --target=i386-pc /dev/sda
update-grub
ls -lh /boot
exit
sudo umount -R /mnt

Tras retirar la ISO y reiniciar desde el disco virtual, Ubuntu volvió a iniciarse correctamente.

5. Instalación dual de Ubuntu y Windows 10

Ampliación del disco virtual

Para disponer de espacio para Windows 10, se amplió el disco virtual de 50 GB a unos 150 GB mediante las herramientas de medios de VirtualBox. Ubuntu inicialmente seguía reconociendo el tamaño anterior, por lo que se creó un clon completo y se continuó trabajando con él.

Creación de la partición EFI en FAT32

El disco ya tenía tabla GPT, pero Ubuntu arrancaba mediante BIOS. Para preparar el modo UEFI se creó una partición de aproximadamente 577 MB en FAT32, identificada como /dev/sda7, con los indicadores boot y esp. Se montó en /boot/efi, independiente de la partición /boot del sistema.

sudo mkdir -p /boot/efi
sudo mount /dev/sda7 /boot/efi
sudo blkid /dev/sda7

Se añadió a /etc/fstab una entrada con el UUID de la partición EFI para montarla automáticamente:

UUID=CECD-BEC0 /boot/efi vfat umask=0077 0 1

Instalación de GRUB para UEFI

Desde Ubuntu, todavía arrancado mediante BIOS, se instaló el soporte de GRUB UEFI. Las órdenes grub-install copiaron los archivos de arranque a la partición EFI; la opción --no-nvram evitó intentar crear una entrada de firmware desde la sesión BIOS. Se creó además una ruta de respaldo con --removable y se actualizó GRUB.

sudo apt install grub-efi-amd64-bin
sudo grub-install --target=x86_64-efi \
  --efi-directory=/boot/efi --bootloader-id=ubuntu --no-nvram
sudo grub-install --target=x86_64-efi \
  --efi-directory=/boot/efi --no-nvram --removable
sudo update-grub

Con la máquina virtual apagada se activó Habilitar EFI en VirtualBox para utilizar el nuevo modo de arranque.

Instalación de Windows 10

Se conectó la ISO de Windows 10 y se inició en modo UEFI. En el instalador se utilizó el espacio sin asignar reservado para Windows, manteniendo las particiones de Ubuntu y la partición EFI FAT32. Windows creó sus particiones auxiliares para completar la instalación.

Incidencia de arranque: apareció grub>

Al priorizar el arranque de Ubuntu desde el gestor del firmware, apareció grub> en lugar del menú. El cargador se había ejecutado, pero no había encontrado automáticamente su configuración. Desde esa consola se buscó el archivo grub.cfg y se cargó manualmente para poder entrar en Ubuntu.

search --file --set=root /boot/grub/grub.cfg
echo $root
configfile ($root)/boot/grub/grub.cfg

Actualización final de GRUB y resultado

Una vez que pude volver a entrar en Ubuntu mediante el menú cargado manualmente, comprobé el estado del disco y actualicé la configuración de arranque.

Primero, utilicé parted para revisar las particiones y confirmar que se conservaban Ubuntu, la partición EFI FAT32 y las particiones de Windows. A continuación, reinstalé GRUB para BIOS y ejecuté la actualización de su menú.

sudo parted /dev/sda print
sudo grub-install --target=i386-pc /dev/sda
sudo update-grub

El comando grub-install terminó sin errores, como aparece en la captura. La orden update-grub se utilizó para regenerar las entradas del menú.

Por último, reinicié la máquina virtual. En lugar de la consola de GRUB apareció el menú normal con las opciones de Ubuntu y Windows Boot Manager.
